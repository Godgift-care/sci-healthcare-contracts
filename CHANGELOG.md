# Changelog

## Unreleased

### Added
- **voucher:** `reduce_amount(funder, voucher_id, new_amount)` lets a funder recover an overpayment without giving up the voucher. While the voucher is still `Funded`, the escrowed amount can be brought down to the clinic's listed price — never below it — and the difference goes straight back to the funder, with no fee taken on money that never became care. The floor is the price the registry lists **at call time**: a raised price cannot be undercut, and a lowered price frees the funder to reduce further. A voucher whose service has been delisted cannot be reduced (there is no price to reduce towards) and is refunded at expiry instead, and a claimed voucher cannot be reduced at all — the amount is what the clinic expects to be paid. The difference leaves escrow, so the running `open_escrow` total reported by `escrow_summary` follows it down. The new `voucher_amount_reduced` event (topics `funder`; data `voucher_id`, `service_code`, `previous_amount`, `amount`, `refunded`) needs one line in the indexer: `voucher_amount_reduced: ['funder']` in `TOPIC_FIELDS` in `sci-healthcare-backend/src/stellar/events.ts`. Its data fields are read by name and need no decoder change; until the line is added the event still decodes, but its `funder` topic reads as `undefined`. The new `AmountNotReduced` error is #22. Closes #89.
- **voucher:** settlement now pays the attester a configurable share of the protocol fee. `Config` gains `attester_share_bps`, set once at initialisation and bounded by `fee_bps` (the new `InvalidAttesterShare`, #21, rejects a larger share), so the attester share is carved out of the fee and never charged on top of the clinic's net. `attest` stores the attester on the voucher, and `settle` pays the clinic `amount - fee`, the attester `amount * attester_share_bps / 10_000`, and the fee account the remainder; the three amounts sum to the voucher exactly. A share of 0 reproduces today's payout, and a dispute resolved for the provider without an attestation has no attester of record, so the fee account keeps the whole fee. `scripts/deploy.sh` defaults to 50 bps (half of the 1% fee) and accepts an `ATTESTER_SHARE_BPS` override. Economics docs, the contract reference and the attester guide are updated, with settlement tests for a non-zero share, a zero share, a full-fee share and the configured bound.
- **voucher:** `refund` now returns a `Funded` voucher immediately when its clinic is no longer active in the registry, instead of making the funder wait for expiry. `refundable_at` reports the current ledger time in that case. `Claimed` vouchers keep the normal seven-day claim grace even if the clinic is later suspended, because care may already have been given. No event or storage layout changes; the existing `voucher_refunded` event is reused, so the backend decoder needs no update.
- **voucher:** `escrow_summary()` returns `(open_escrow, token_balance)`, a read-only solvency check anyone can run. `open_escrow` is a running instance-storage total, increased by `create_voucher` and decreased by `settle`, `refund` and both outcomes of `resolve_dispute`; `token_balance` is the contract's real token balance. Lifecycle tests assert the two stay equal after every operation, so an accounting bug is caught rather than hidden. Closes #132.
- **faucet:** a per-address lifetime cap. `FaucetConfig` and `initialize` gain `lifetime_cap`: the total base units one address may ever receive, with `0` meaning unlimited. A persistent per-address counter is TTL-extended on every read and write, and a drip past the cap is rejected with the new `LifetimeCapReached` (#8) even on a new UTC day. Closes #131.
- **docs:** a [testing guide](CONTRIBUTING.md#testing) covering fixtures for the registry, receipt book and token, time travel with `timestamp` and `sequence_number`, asserting `env.auths()`, decoding events and pinning typed errors with the generated `try_*` methods. The same section is in [the docs copy](docs/developers/contributing.md#testing). Closes #130.
- **docs:** a Mermaid sequence diagram of the claim → attest → dispute → resolution flow in [How a voucher works](docs/protocol/lifecycle.md#the-dispute-sequence), including the no-dispute settlement path and the claim-grace refund when no attestation arrives. Closes #113.
- **test:** every error variant in `VoucherError`, `RegistryError`, `ReceiptError` and `FaucetError` now has a dedicated test that triggers it, satisfying the requirement that all error codes are reachable and tested. Closes #109.
- **ci:** `unwrap()` and `expect()` are now denied in contract code (outside tests) via `#![deny(clippy::unwrap_used, clippy::expect_used)]` gated to non-test builds. Existing uses were replaced with proper error returns. CI fails on any new unwrap in contract code. Closes #110.

Includes module-level docs, struct/field docs, enum variant docs, constant docs, and function docs with param/return/error descriptions. `cargo doc` now builds with no missing-docs warnings on hand-written items.
- **receipt:** a per-provider receipt index and `receipts_of_provider(provider, start, limit)`, so a clinic can prove its track record to a funder or auditor without the indexer. `mint` appends each voucher id to the provider's index in mint order; the view pages with `start` and caps `limit` at `MAX_RECEIPTS_PAGE` (50). Two clinics' receipts never mix, and `ProviderCount` / `ProviderReceipt` entries are TTL-extended on read like every other persistent entry. Closes #105.

Closes #98.
- **registry:** clinics schedule price changes instead of springing them. `schedule_service_price(provider_addr, code, price, effective_at)` stores `pending_price` and `effective_at` on the service, requires at least `MIN_PRICE_NOTICE_SECS` (24 h) of notice (`PriceNoticeTooShort`, #12) and emits `service_price_scheduled { provider, code, price, effective_at }`. - **voucher:** a daily attestation cap per attester. `attest` counts each attester's attestations per UTC day in temporary storage keyed by `(attester, day)` and rejects any beyond the cap with `AttestationCapReached` (#19); the count resets at midnight UTC. The cap defaults to `DEFAULT_MAX_ATTESTATIONS_PER_DAY` (100) and the admin changes it with `set_attestation_cap(admin, cap)` (`InvalidAttestationCap`, #20, for 0), which emits `attestation_cap_changed { admin, cap }`. `get_attestation_cap` and `attestations_left(attester)` are views. A stolen attester key can now confirm at most one day's cap before the admin removes it. Closes #100.

### Changed
- **voucher:** `voucher_settled` gains `attester_share` (the part of `fee` paid to the attester), appended after the existing fields. Topics are unchanged and the data map is keyed by name, so decoders that read by field name pick it up without a breaking change. `attester_share + (fee - attester_share) == fee`, and `net + fee == amount` still holds.
- **receipt:** `set_minter(admin, minter)` is replaced by `propose_minter` / `accept_minter` (see Added). `scripts/deploy.sh` now initialises the receipt book with the voucher contract as minter directly, because both instances are deployed before either is initialised; later changes go through the two-step handover.
- **voucher:** `quote` and `settle` are covered by a lifecycle test for a range of amounts, including the rounding cases and the largest fundable amount, so a quote shown before signing is proven to match what settlement pays. (#108)
- **voucher:** `voucher_attested` carries `remaining_today`, appended after the existing fields: the attestations that attester has left today. Topics are unchanged and the data map is keyed by name, so decoders that read by field name pick it up without a breaking change. (#100)
- **registry:** `upsert_service` no longer raises the price of an existing service; it returns `PriceIncreaseNeedsNotice` (#13) and the rise goes through `schedule_service_price`. Listing a new service and lowering a price still apply at once. `ServiceItem` gains `pending_price` and `effective_at`. (#99)
- **receipt:** `count_for` now extends the TTL of the count entry it reads. It was the only persistent read in the three contracts that did not, so a patient's episode count could be archived while their receipts stayed live. Covered by `count_for_extends_its_own_entry`.
- **scripts:** `scripts/deploy.sh` now refuses to overwrite an existing `deployments/<network>.env` unless `--force` is passed, so an accidental second run cannot replace the live addresses. `--dry-run` prints every command without building, deploying or sending a transaction, and the final summary makes the outcome explicit. `scripts/test-deploy.sh` covers the refusal, `--force` and dry-run paths without a network, and the new `deploy script` CI job runs it on every pull request.
- **deploy:** `scripts/deploy.sh` and `scripts/deploy-faucet.sh` deploy the wasm that `scripts/build-wasm.sh` produces, so what is deployed is what is released. The faucet used to be built on its own (`cargo build -p sci-faucet`), which links a different `soroban-sdk` than the rest of the workspace and produces different bytes.
- **build:** the build takes the cargo registry path out of the wasm (`--remap-path-prefix`). The Soroban SDK embeds the absolute path of its own source in its panic messages, so the artefact used to carry the builder's home directory, and two machines never agreed on its hash.
- **cargo:** the workspace path dependencies carry a version, so `cargo deny` does not read them as wildcard version requirements.
- **voucher:** `voucher_claimed`, `voucher_attested`, `voucher_disputed`, `voucher_settled` and `voucher_refunded` now carry `service_code` and `amount` in their data, appended after the fields each event already had. Only `voucher_created` used to say what the voucher was for, so an indexer or wallet reading a single lifecycle event had to load the voucher to show what was paid for. `voucher_refunded` already carried `amount`; it gains `service_code` only. Topics are unchanged and the data map is keyed by name, so the indexer in `sci-healthcare-backend` decodes the new layout without a breaking change (its matching decoder change is linked from the pull request). Covered by five event snapshot tests in `contracts/voucher/src/test.rs` that read the decoded XDR event and the regenerated `test_snapshots`.

Tests: 222 (was 195).

## 0.2.0 — 2026-10-09

Redeployed to testnet on 2026-10-07; addresses are in `deployments/testnet.env`.

### Fixed
- **voucher:** a `Claimed` voucher that is never attested no longer locks the funder's money forever. `refund` accepts it seven days (`CLAIM_GRACE_SECS`) after expiry.
- **voucher:** a provider suspended after a voucher was funded can no longer `claim` it.
- **voucher:** every state transition extends the instance TTL, not only `create_voucher`.
- **registry:** attester entries are TTL-extended on read like providers and services.

### Added
- "Try it in five minutes" walkthrough in the README.
- Issue forms (bug, feature) and a pull request template; blank issues off, security reports routed to SECURITY.md.
- **faucet** (testnet only): anyone can get 50 test USDC once a day from the app, with no server holding the issuer key. The demo token's SAC names the faucet as admin; `release_token_admin` hands it back. Deployed by `scripts/deploy-faucet.sh`, which refuses mainnet. 10 tests.
- Two-step admin handover (`propose_admin` / `accept_admin` / `get_pending_admin`) in registry, voucher and receipt. Replaces the registry's one-step `set_admin`; the voucher admin previously could not be rotated at all.
- `refundable_at(voucher_id)` view on the voucher contract.
- Documented dispute reason codes 1–4.

Tests: 94 (was 69).
