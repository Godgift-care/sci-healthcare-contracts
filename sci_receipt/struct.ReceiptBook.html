pub fn initialize( env: Env, admin: Address, minter: Address, ) -> Result<(), ReceiptError>

Sets the admin and the minter. Callable exactly once.

minter is the voucher contract address. Contract instances are deployed before either is initialised, so the voucher address is known here; changing it later goes through propose_minter and accept_minter.

Source

pub fn propose_minter( env: Env, admin: Address, new_minter: Address, ) -> Result<(), ReceiptError>

Nominates a new minter. Takes effect only once they accept.

Two steps so a typo in the new address cannot let the wrong contract mint receipts, or stop receipts entirely. Proposing again replaces the earlier nominee. minter is normally a redeployed voucher contract.

pub fn accept_minter(env: Env, new_minter: Address) -> Result<(), ReceiptError>

The nominated address accepts and becomes the minter.

pub fn mint( env: Env, minter: Address, voucher_id: u64, beneficiary_ref: BytesN<32>, provider: Address, service_code: u32, amount: i128, fee: i128, net: i128, ) -> Result<(), ReceiptError>

Records a settled care episode. Callable only by the minter.

amount is the gross value of the voucher, fee the protocol fee taken from it and net what the provider received. They must add up: net + fee == amount. The voucher contract passes the same three numbers it paid out, so a receipt can be reconciled without the settlement event.

pub fn get_receipts(env: Env, ids: Vec<u64>) -> Vec<Receipt>

Reads several receipts in one call, in the order the ids were given.

A care summary reads a patient’s history in one simulation instead of one per receipt. Unknown ids are skipped rather than failing the whole call, so a page built from an index that has since changed still returns everything it can. At most MAX_RECEIPTS_PER_CALL ids are read; the rest are ignored, exactly like unknown ids. No signature is required, and every receipt read is TTL-extended like get_receipt.

Source

pub fn count_for(env: Env, beneficiary_ref: BytesN<32>) -> u32

How many settled care episodes this beneficiary reference has.

Extends the counter’s TTL like every other persistent read: a patient who keeps being treated must not have their history archived out from under them because only the receipt entries were being extended.

Source

pub fn provider_stats(env: Env, provider: Address) -> (u32, i128)

A clinic’s on-chain track record: (count, total_amount).

The count is the receipts minted for this provider and the total is the sum of their amounts, in the same base units the receipts carry. Exact and read-only: no signature, no indexer. A provider with no receipts returns (0, 0). Both entries are TTL-extended on read like every other persistent entry, so a clinic’s record is not archived out from under it while it is being read.

Source

pub fn receipts_of_provider( env: Env, provider: Address, start: u32, limit: u32, ) -> Vec<Receipt>

A clinic’s receipts in mint order, newest last.

start is the index of the first receipt to return; limit is capped at MAX_RECEIPTS_PAGE so one read cannot exceed host limits. Page by calling again with start += returned.len(). A provider with no receipts returns an empty list, and one clinic’s index never includes another clinic’s receipts.

Source

pub fn name(env: Env) -> String

Human-readable name shown by wallets and explorers.

Read-only view, no signature required. Receipts are soulbound: there is no transfer function, so a receipt stays bound to the beneficiary reference it was minted against.

Source

pub fn symbol(env: Env) -> String

Token-style symbol shown by wallets and explorers.

Read-only view, no signature required. Receipts are soulbound.

pub fn receipt_uri(env: Env, voucher_id: u64) -> String

Read-only, per-receipt URI for explorers and wallets.

The URI is derived only from voucher_id. It contains no patient or beneficiary data — it is an opaque pointer to the receipt, not the care record itself. No signature required.
