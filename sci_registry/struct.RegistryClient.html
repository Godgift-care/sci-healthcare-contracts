pub fn set_provider_status( &self, admin: &Address, provider_addr: &Address, status: &ProviderStatus, reason_code: &u32, )

Moves a provider between lifecycle states. Admin only.

Only the four informative transitions are accepted — Pending → Active, Pending → Suspended, Active → Suspended and Suspended → Active. Setting the same status again, or moving a provider backwards to Pending, is refused with InvalidTransition instead of emitting an event that misleads the indexer and anyone auditing the registry’s history. Entering Retired is likewise not the admin’s call: the provider’s own owner leaves with retire.

reason_code is the documented reason for the change (see docs/protocol/trust.md); it is stored on the provider and emitted with the status, so a suspended clinic knows why and a funder can tell a fraud suspension from a paperwork one. Code 0 is reserved for “no status change yet” (written by registration) and is refused with MissingReasonCode, so every change — reinstating a suspended clinic included — records a real reason. Only the stored admin, signing, can call this; the check runs before anything else is read.

When a provider becomes Active, they are added to the per-country index so providers_in can find them. When they become non-Active (e.g. Suspended), they are removed from the index using swap-and-pop so the index stays consistent and reads remain O(1) amortized.

pub fn retire(&self, owner: &Address, reason_code: &u32)

Lets a provider withdraw from the registry. Its own owner only.

Clinics close, and a closed clinic that stays listed keeps drawing funders’ money into escrow it will never claim. retire sets the terminal Retired status: the clinic immediately stops being an active provider, so voucher refuses to fund it any new vouchers and an unclaimed one refunds without waiting for expiry, while a voucher claimed before the clinic retired still attests and settles as care delivered.

Nothing can move a retired clinic back in, not even the admin: it must register again. Retiring an already-retired clinic is refused with InvalidTransition, so the lifecycle history stays free of no-op events. reason_code follows the same documented codes as set_provider_status (see docs/protocol/trust.md).

pub fn upsert_service( &self, provider_addr: &Address, code: &u32, label: &String, price: &i128, )

Creates or updates a service the provider bills for.

Only an Active provider may maintain a catalog, so a suspended clinic cannot quietly re-price itself back into circulation.

A new service is listed at price straight away, and so is a lower price for an existing one. Raising an existing price is rejected with PriceIncreaseNeedsNotice: use schedule_service_price, so a funder never sees one price and finds another minutes later. A price already scheduled is left in place.

pub fn schedule_service_price( &self, provider_addr: &Address, code: &u32, price: &i128, effective_at: &u64, confirm_large_change: &bool, )

Schedules a new price for a listed service, effective at effective_at.

The time must be at least MIN_PRICE_NOTICE_SECS away, so apps can warn funders before it lands. Until then get_service_price keeps returning the current price; from then on it returns this one. Scheduling again replaces the earlier schedule, and scheduling the current price is how a clinic calls one off.

A price of MAX_PRICE_JUMP times the current price or more is rejected with LargePriceJumpNeedsConfirmation unless confirm_large_change is true. A 5x increase is almost always a mistyped zero, and every funder that day would pay it, so the clinic has to say so explicitly.

pub fn set_capacity(&self, provider_addr: &Address, max_outstanding: &u32)

Declares how many vouchers this clinic can have outstanding (funded but not yet settled or refunded) at once. 0 means unlimited, which is also the default for a clinic that never sets it.

voucher refuses to fund a new voucher at a clinic already at its capacity (ProviderAtCapacity), so funders’ money is not stuck at a clinic that cannot see the patients before the vouchers expire. Lowering the capacity below the current count affects only new vouchers; outstanding ones settle or refund as normal.

Providers in registration order, paged by start and limit.
